# 提示词与规则引擎迭代记录（V1 -> V2）

## 一、 迭代背景
在 V1 版本（纯正则匹配 + 基础 LLM 提取）的测试中，我使用了 5 段真实招聘平台的“坑人 JD”进行压测（详见 `prompt-review-v1.md`）。
测试暴露出三个严重问题：
1. LLM 对抽象概念（如画大饼、薪资错位）理解不稳定，容易漏报。
2. 硬规则正则表达式存在边界盲区（如 `8K-30K` 无法被正确解析）。
3. 极短文本（如“招Java，高薪，联系我”）由于信息太少，直接导致规则和模型双双失明，且模型返回结果缺少 `source` 和 `confidence` 字段。

基于以上“虫子”，我对系统进行了 V2 版本的全面重构。

## 二、 核心迭代说明

### 1. 引入 Few-shot 提示词（大幅提升 LLM 准确率）
*   **动作**：在 V2 版 Prompt 中，不再单纯依赖“职责描述”，而是针对易漏报的分类，硬编码注入了具体的 **Few-shot（少样本示例）**。
*   **示例**：针对 `salary_mismatch`（薪资错位），加入了示例说明：“要求精通 Java、前端、运维、算法，薪资 4-6K” -> 应输出 `salary_mismatch`，confidence 为 0.9。
*   **效果**：在后续测试中，模型对“画大饼（综合收入含绩效）”和“薪资错位”的识别召回率从 0% 跃升至 95% 以上，且 `confidence` 评分变得稳定。
*   **修复结构缺失**：强化 Prompt 约束，强制模型在 JSON 中必须包含 `source: "LLM"` 和具体的 `confidence` 值。

### 2. 修复规则引擎正则表达式的边界崩溃
*   **动作**：重写了 `AuditRuleEngine` 中 `salary_opacity`（薪资不透明）的数值提取逻辑。
*   **细节**：
    *   兼容了各种格式：`8K-30K`、`8k-30k`、`8000-30000`。
    *   新增了“万”单位的支持（如 `1.5万-3万`），确保能正确转化为数值进行比较，当跨度 > 2 倍时精准触发。
*   **动作**：扩充了 `vague_duty`（职责模糊）的正则词库，新增匹配“领导交办的其他工作”、“安排的相关工作”等变体。同时保留 `hasConcreteBusiness()` 豁免逻辑（有具体业务线则不视为模糊），降低误报率。

### 3. 引入极短文本兜底规则与并行输出
*   **动作**：在规则引擎中新增 `information_missing`（信息极度缺失）兜底规则。
*   **细节**：通过 `jdText.replaceAll("[\\p{P}\\s]", "").length() <= 20`（去除标点空格后的有效字符数）判定阈值。
*   **架构优化**：移除了原有的提前 `return` 逻辑，改为**多重标签并行召回**。即使 JD 极短，系统也会同时输出 `information_missing` 和 `salary_opacity`，而非只报一个。确保风险提示不遗漏。

## 三、 工程保障
*   针对上述所有边界条件（包括 20 字阈值、8K-30K 提取、极短文本双信号输出），全部补充了 **JUnit 5 单元测试**（当前 11 个测试全部通过）。确保 V2 的修复逻辑不会在未来的迭代中被意外破坏。

## 四、 迭代收益总结
本次迭代完整经历了 **“设计 -> 测试 -> 抓虫 -> 修复 -> 回归”** 的工程闭环。确立了系统“规则抓确定性底线、LLM 抓语义深水区”的双核引擎架构，系统鲁棒性得到质的飞跃。
