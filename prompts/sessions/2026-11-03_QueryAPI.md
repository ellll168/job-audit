## 第 1 轮：实现 GET /api/audits/{id} 查询接口

### 用户提问

> @.trae-context.md 今天我们要实现根据 ID 查询审计记录的接口。
> 要求：
>
> 在 domain 包下新建一个返回给前端的 DTO 类，命名为 AuditResultResponse。它需要包含主记录的字段（auditId, companyName, inputText, status, createdAt），以及一个 List&lt;AuditSignalRecord&gt; 字段用来装关联的信号列表。
>
> 在 api 包下的 JobAuditController 中新增 GET /api/audits/{id} 接口。
>
> 接口逻辑：先根据 id 查询 job_audit 表，如果不存在，返回 404 或者抛出业务异常。再根据 id 查询 audit_signal 表，拿到所有的信号。将两者组装到 AuditResultResponse 中返回。
>
> 请在控制台打印包含 traceId 的日志，记录这次查询动作。

### 处理过程

1. `AuditResultResponse`：record，5 个主记录字段 + `List<AuditSignalRecord> signals`。
2. "不存在"的处理选择：为保持 `ErrorResponse` 统一错误格式，采用"业务异常 + @ControllerAdvice"方案而非 `ResponseEntity.notFound()`——新建 `exception` 包放 `AuditNotFoundException`，`GlobalExceptionHandler` 增加 404 处理器。
3. Controller 用 `selectById` 查主表，`QueryWrapper.eq("audit_id", id).orderByAsc("id")` 查关联信号。
4. 编辑插曲：一次 Edit 误删了 `toRecord()` 方法体，发现后立即补回并插入新方法，编译验证无碍。

```java
    @GetMapping("/{id}")
    public AuditResultResponse getById(@PathVariable Long id) {
        String traceId = UUID.randomUUID().toString();
        MDC.put("traceId", traceId);
        try {
            log.info("查询审计记录，auditId={}", id);

            JobAudit jobAudit = jobAuditMapper.selectById(id);
            if (jobAudit == null) {
                throw new AuditNotFoundException(id);
            }

            List<AuditSignalRecord> signals = signalRecordMapper.selectList(
                    new QueryWrapper<AuditSignalRecord>().eq("audit_id", id).orderByAsc("id"));
            log.info("查询完成，auditId={}，关联信号数={}", id, signals.size());

            return new AuditResultResponse(
                    jobAudit.getId(),
                    jobAudit.getCompanyName(),
                    jobAudit.getInputText(),
                    jobAudit.getStatus(),
                    jobAudit.getCreatedAt(),
                    signals);
        } finally {
            MDC.remove("traceId");
        }
    }
```

### 验证结果

- `GET /api/audits/2` → 200，主记录 + 5 条信号完整返回，中文正常
- `GET /api/audits/9999` → `404 {"code":404,"message":"审计记录不存在，id=9999",...}`

### 发现的问题

404 的 WARN 日志中 traceId 为空（`[]`）——Controller 的 `finally` 在异常传播到 `@ControllerAdvice` 之前就已 `MDC.remove`。由此引出第 2 轮重构。

## 第 2 轮：TraceId 管理上移到 OncePerRequestFilter

### 用户提问

> 好的，这是一个非常关键的架构问题，请帮我重构。
> 要求：
>
> 新建一个实现 OncePerRequestFilter 的 TraceIdFilter 类。
>
> 在 doFilterInternal 方法中，请求入口生成 UUID 作为 traceId 并放入 MDC。
>
> 使用 try-finally 包裹 filterChain.doFilter()，在 finally 中调用 MDC.clear() 防止线程池复用导致的内存泄漏。
>
> 删除 Controller 里原本手动操作 MDC 的代码，让 Controller 只负责通过 MDC.get("traceId") 取值。
>
> 确保全局异常处理器 GlobalExceptionHandler 里也能打印出这个 traceId。

### 处理过程

1. 新建 `TraceIdFilter`（api 包）：`OncePerRequestFilter` + `@Component`（Spring Boot 自动注册 Filter Bean 进 Servlet 链），常量 `TRACE_ID = "traceId"` 供各处引用。
2. Controller 两个接口删除全部手动 `MDC.put/remove` 与 UUID 生成，日志改用 `MDC.get(TraceIdFilter.TRACE_ID)` 取值；移除多余的 `UUID` import。
3. `GlobalExceptionHandler` 零改动获得 traceId 能力——Filter 是请求最外层，`@ControllerAdvice` 运行在 `filterChain.doFilter()` 内部，清理发生在响应发出之后。

### 生成的完整代码

`TraceIdFilter.java`：

```java
package com.example.jobaudit.api;

import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.slf4j.MDC;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;

import java.io.IOException;
import java.util.UUID;

/**
 * TraceId 过滤器：请求入口生成 UUID 放入 MDC，请求结束统一清理。
 * 注册为 Spring Bean 后自动加入 Servlet 过滤链，覆盖 Controller 与 @ControllerAdvice。
 */
@Component
public class TraceIdFilter extends OncePerRequestFilter {

    public static final String TRACE_ID = "traceId";

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        MDC.put(TRACE_ID, UUID.randomUUID().toString());
        try {
            filterChain.doFilter(request, response);
        } finally {
            MDC.clear();
        }
    }
}
```

Controller 重构后的两个接口（核心部分）：

```java
    @PostMapping
    public AuditResponse create(@Validated @RequestBody AuditRequest request) {
        log.info("收到岗位审计请求，traceId={}，companyName={}", MDC.get(TraceIdFilter.TRACE_ID), request.companyName());

    }

    @GetMapping("/{id}")
    public AuditResultResponse getById(@PathVariable Long id) {

    }
```

## 架构收益

- traceId 生命周期只归 Filter 一处管理，新增 Controller / 异常处理器自动继承，杜绝"忘记埋点"与"清理时机错误"两类问题。
- `MDC.clear()` 在 `finally` 中兜底，Tomcat 线程池复用不会残留上下文。
