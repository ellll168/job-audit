# Prompt V1 测试与缺陷记录 (2026-11-06)

## 一、 测试背景
使用 5 段真实风格的“坑人 JD”对“规则引擎 + LLM 语义提取”混合架构进行首轮压测。
- 测试目标：验证 LLM 结构化输出的稳定性、JSON 解析成功率，以及规则与模型的互补召回率。
- 测试结果：闭环跑通，系统未因异常崩溃（触发降级逻辑生效），但发现 6 处明显的“漏报/误报”缺陷。

## 二、 缺陷清单（Bug Report）

### 🐛 虫子 1：LLM 结构缺失（已修复）
- **现象**：早期版本中，LLM 提取的信号缺少 `source` 和 `confidence` 字段，导致前端无法区分信号来源。
- **根本原因**：DTO 组装层（Service）未将解析后的实体字段完整映射。
- **修复状态**：已通过让 AI 修改组装逻辑，并在 Prompt 中加入强约束。目前 `source` 已正确标记为 "LLM"，`confidence` 正常返回数值。

### 🐛 虫子 2：过度包装漏报（待优化 Prompt）
- **现象**：第 2 段 JD（PUA画大饼型）中，LLM 成功识别了“狼性精神”（pua_culture），但漏掉了“广阔发展空间、扁平化管理、年轻化团队”等极其典型的 `overpackaged`（过度包装）信号。
- **根本原因**：V1 版 Prompt 对 `overpackaged` 的定义不够具体，缺乏具体的 Few-shot 示例引导模型。

### 🐛 虫子 3：正则表达式漏报（待修复代码）
- **现象**：第 3 段 JD 中明确写了“偶尔兼顾行政事务及领导交办的其他工作”，但硬规则引擎未输出 `vague_duty` 信号。
- **根本原因**：AI 最初写的正则表达式只匹配了“完成相关工作”，漏掉了“安排的其他相关工作”等同义词变体。
- **修复方向**：扩充规则引擎的正则表达式词库（或改用关键词包含匹配）。

### 🐛 虫子 4：薪资与要求错位未识别（待扩充 Taxonomy）
- **现象**：第 3 段 JD 要求精通 Java、Python、Vue、运维等全栈技术，但薪资仅给 4-6K。规则和 LLM 均未针对这种“极高要求+极低薪资”的离谱反差输出专门信号。
- **修复方向**：在系统的分类体系（Taxonomy）中新增一类 `salary_mismatch`（薪资要求错位）信号，并补充进 Prompt。

### 🐛 虫子 5：语义盲区 / 信息黑洞（待补充兜底规则）
- **现象**：第 4 段 JD（“招Java，高薪，联系我。面议。”）极度简短。硬规则触发了“面议”预警，但 LLM 因为文本过短，直接返回了空数组 `[]`，未给出任何风险提示。
- **根本原因**：模型在没有足够上下文时选择“闭嘴”保护自己。但现实中，信息极度缺失本身就是巨大的风险。
- **修复方向**：增加一条兜底硬规则：“若 JD 文本长度 < 20 字，直接输出 `information_missing` (HIGH) 信号，要求求职者高度警惕”。

### 🐛 虫子 6：薪资数值解析失效（待修复代码）
- **现象**：第 5 段 JD 写明“8K-30K”，跨度远超 2 倍，但硬规则未能触发 `salary_opacity` 报警。
- **根本原因**：AI 写的正则提取逻辑在处理“带有大写 K 和横杠”的混合字符串时失效，未能成功提取出数值（8 和 30）进行大小比较。
- **修复方向**：重写薪资提取的正则表达式，并增加边界值测试（如：8k-30k, 8K~30K, 8000-30000）。

## 三、 明日迭代计划 (11.7)
1. **修代码**：让 AI 修复正则引擎（虫子 3 和 虫子 6），让规则引擎恢复火力。
2. **加兜底**：增加字数极短（<20字）的拦截规则（虫子 5）。
3. **改 Prompt (Few-shot)**：针对虫子 2 和 4，在 V2 版 Prompt 中，给 `overpackaged` 和 `salary_mismatch` 补充具体的示例文本，教大模型如何识别。
